## 1. 名詞

- **期 t**：雙色球一期，以官方期號 `issue`（7 位數，例 `2026126`）標記。
- **issueDate(t)**：官方開獎日在 Asia/Shanghai 的公曆日期。
- **停售時間 cutoff(t)**：開獎日 20:00 Asia/Shanghai（絕對時間）。
- **池 pool_t**：第 t 期的候選組合集合，K 組，每組 = 6 紅（1–33）+ 1 藍（1–16）。
- **picks**：B = 2,000 個合成生辰，每個生辰 b 在第 t 期依規則 v1 從 pool_t 選出一組 `pick_{b,t} ∈ pool_t`。
- **draw_t**：第 t 期官方開獎號碼。
- **分數** `s(c, d) = |紅(c) ∩ 紅(d)| + [藍(c) = 藍(d)]`，範圍 0–7。

## 2. 歷史窗暖機 W（Eng F1 / D2）

- 官方 3–6 等注數只從 `2013001` 起才有，2003–2012 做不出人氣池，**不進紫微實驗**（擂台和帳本照舊使用）。

- 不管最後採用哪一種池產生器，W 都一樣（見 §6），讓兩種產生器的歷史窗相同。
- **歷史窗** = 第 `2013001` 起算的第 W+1 期，到「規則凍結時間之前最後一期已開獎的期」為止。期數範圍凍結時寫入 `control/hist-v1.json` 的 `first_issue`、`last_issue`，之後不再變動。

## 4. 主檢定：鞅 z 檢定（Eng D13）

每一窗（歷史窗、前瞻窗）各做一次，互不相加。

**每期統計量：**

```
X_t = (1/B) Σ_b s(pick_{b,t}, draw_t) − (1/K) Σ_{c∈pool_t} s(c, draw_t)
```

**為什麼是鞅差：** pool_t 只用 < t 期的資料產生（§6，CEO O1）；pick_{b,t} 只依生辰、issueDate(t) 和 pool_t 決定。所以給定過去，pool_t 和 picks 都已決定，draw_t 才是唯一的隨機來源。H0（紫微選的組和池內均勻挑的組沒有差別；開獎均勻）下 `E[X_t | F_{t−1}] = 0`。

**條件變異數（精確，不用模擬）：** 把 X_t 寫成池內加權和 `X_t = Σ_{c∈pool_t} w_c · s(c, draw_t)`，`w_c = n_c/B − 1/K`，n_c = 選到 c 的生辰數（Σ w_c = 0）。則 `Var_t = wᵀ Σ_t w`。開獎是均勻的（紅 C(33,6)、藍 1/16，紅藍獨立），兩組 a、b 的分數共變異數：

```
Cov(s_a, s_b) = Cov_紅 + Cov_藍
Cov_紅 = m·p(1−p) + (36 − m)(q − p²)      m = |紅(a) ∩ 紅(b)|，p = 6/33，q = 6·5/(33·32)
Cov_藍 = [藍(a) = 藍(b)]/16 − 1/256
```

（a = b 時 m = 6、藍相同，就是單組的變異數。）

**檢定：**

```
Z = Σ_t X_t / √(Σ_t Var_t)       （t 走遍該窗的有效期）
p = 2·(1 − Φ(|Z|))               雙尾常態近似
```

- 顯著水準：每窗 α = 0.025（雙尾），兩窗 Bonferroni 合計 0.05。
- 報告 `D̄ = Σ_t X_t`（N 期合計平均多命中的球數）、每期平均 `D̄/N`、Z、p、MDE（§5）。
- p ≥ 0.025 只能寫「未達預先登記的顯著標準；這不代表證明沒有效果」（Eng D14）。
- **敏感度分析（不用來判決）：** 固定池和 picks，模擬均勻開獎 10,000 次，每次重算 D̄_sim，求經驗雙尾 p。種子見 §8。
- 計算者：Python 統計模組（Eng D6；E3 任務 `pipeline/ziwei_stats.py`）。ziwei-lab 只輸出 `picks/*.json`。

## 5. 最小可測效果 MDE（Eng D15）

每窗在看開獎**之前**算出，只用該窗的池和 picks：

```
MDE_total = (z_{1−α/2} + z_{0.80}) · √(Σ_t Var_t)
          = (2.2414 + 0.8416) · √(Σ_t Var_t) = 3.0830 · √(Σ_t Var_t)
MDE_per   = MDE_total / N
```

- α = 0.025 雙尾，檢定力 80%；假設對立假說下的變異數近似 H0 的 Var_t。
- 單位和 D̄ 一樣（多命中的球數）。
- 歷史窗：凍結後、跑檢定前算出並寫入 `verdict/hist-v1.json`。前瞻窗：用前 300 個有效期的池和 picks 算出，和檢定結果一起發布（只用池和 picks，不看開獎，所以可以在第 300 期開獎前先算）。
- 判決書卡一律顯示 MDE。

## 6. 池產生器的選定（Eng D17 / CEO O1）

**選定程序（凍結前執行，結果填入下表後才凍結）：**

1. 執行前一份設計的人氣模型 holdout 關卡（E2 任務 `pipeline/pools.py`）。
2. 通過 → 兩窗都用 **as-of 人氣模型池**；不通過 → 兩窗都用 **結構規則池**，而且**不宣稱冷門指數**。
3. 選定後兩窗都不換產生器（R1 勘誤除外）。前瞻窗可以升級人氣模型的 `model_version`（同一種產生器），歷史窗不跟著重算。

**as-of 規則（兩種產生器都適用）：** 第 t 期的池只能用 `issue < t` 的開獎和中獎資料（walk-forward）。產生器輸入裡出現第 t 期或更晚的任何資料都算違規。測試：注入第 t 期極端值，pool_t 必須不變。

**結構規則池（備案）定義：** 從所有組合中排除以下各類：

- 紅球全部 ≤ 31；
- 6 個紅球是等差數列，或有 4 個以上連號（例 05,06,07,08）；
- 和上一期開獎紅球完全相同。

然後用第 t 期的種子（§8）從剩下的組合均勻抽 K 組（不重複）。

**精確抽法（`pool-struct-v1`，實作 `pipeline/pools.py: struct_pool`）：** `rng = np.random.default_rng(seed_t)`；每個候選先 `reds = sorted(rng.choice(33, 6, replace=False) + 1)`，再 `blue = rng.integers(1, 17)`。命中任一排除規則、或 `(reds, blue)` 與已收的組重複，就丟掉重抽（拒絕抽樣，保持均勻）；收滿 K 組為止。藍球不受排除規則限制。「上一期」= 全部歷史（含 500 來源的 `numbers_only` 期）中 issue < t 的最大一期；第 t 期本身不必已在歷史中。等差 = 任意公差；連號 = 長度 ≥ 4 的連續段。golden 測試釘住 2026125 期的前 3 組。

## 7. 封籤格式 LLSEAL1 與 engineTag（Eng F4 / D5，CEO O3）

LLSEAL1 是單向門：第一張籤發出後格式就不能改，只能另立 `LLSEAL2`。

```
commit = SHA-256( UTF-8(
  "LLSEAL1|" + issue + "|" + ruleVersion + "|" + engineTag + "|" + poolVersion
  + "|" + 紅球升冪、兩位數、逗號連接 + "|" + 藍球兩位數 + "|" + salt_hex ) )
```

| 欄位 | 格式 |
|---|---|
| issue | 7 位數字 |
| ruleVersion | `ziwei-v1` |
| engineTag | `<ZiweiKit git tag>+<實驗口徑 id>`，例 `ziweikit-v1.0.0+exp1` |
| poolVersion | 該期池檔的 `pool_version` |
| 紅球 | 6 個，升冪，各兩位數，`,` 連接 |
| 藍球 | 兩位數 |
| salt_hex | 16 bytes 隨機鹽，32 個小寫十六進位字元 |
| commit 輸出 | 64 個小寫十六進位字元 |

- 所有欄位都不得含 `|`；engineTag、poolVersion 只能用 `[A-Za-z0-9._+-]`。
- **實驗口徑 id**：固定成原版引擎預設（正月初一換年、亮度《斗數全書》、`DEFAULT_LEAP_MONTH`、晚子時 23:00 換日），和 App 的顯示流派設定分開。實驗用的 engineTag = `ziweikit-v1.0.0+exp1`（ZiweiKit git tag `ziweikit-v1.0.0` + `exp1`）。
- **引擎鎖定**：凍結時把 ZiweiKit tag、golden 集合雜湊寫入 log。golden 集合雜湊 = tag 上 `golden/` 內所有受版控檔案，逐檔 SHA-256 後按路徑排序成 `<sha256>  <路徑>` 各一行，整串再取 SHA-256（指令見 `lab/log.md`）。之後修引擎比照 R1：舊 picks 標「已撤回」，新 engineTag 重跑，兩版並列。

**格式範例（只示範格式，不是真的籤）：**

```
preimage = LLSEAL1|2026126|ziwei-v1|ziweikit-v1.0.0+exp1|pool-struct-v1|03,07,12,19,25,31|09|00112233445566778899aabbccddeeff
commit   = a054a6875a4746130b0c073225c76117a7fe69021396652ff294ea244c68fcd7
```

ZiweiPick 的固定向量測試要用這組範例重現同一個 commit。

## 9. 輸入與合成生辰

- **輸入**：生辰正規化字串 `曆法(S/L)|年|月|日|閏月(0/1)|時間|性別(M/F)|經度|utcOffset|夏令時開關(0/1)`（由 ZiweiKit `BirthInput` 解析，範圍 1900–2100）。排盤一律用實驗口徑（§7），和 App 的顯示設定無關。
- **2,000 個合成生辰**，用 §8 的種子和 `default_rng`，依序對 b = 0…1999 抽：
  1. 日期：1950-01-01 到 2010-12-31（公曆，含頭尾）之間均勻抽一天；
  2. 時辰：timeIndex 從 0–12 均勻抽（早子、晚子分開算）；
  3. 性別：M / F 各 1/2；
  4. 固定欄位：曆法 `S`、閏月 `0`、經度 `+120.0000`、utcOffset `+480`、夏令時 `0`。

  亂數呼叫順序（每筆依序）：`day = rng.integers(0, 22280)`（自 1950-01-01 起的天數）、`timeIndex = rng.integers(0, 13)`、`sex = rng.integers(0, 2)`（0 = M）。實作 `tools/golden-gen/inputs.py`。timeIndex 12（晚子）排盤時視為次日子時（原版 `next-day` 口徑）。

  每筆的字串格式是 `S|YYYY|MM|DD|0|B<timeIndex>|<M/F>|+120.0000|+480|0`。清單一行一筆、以 `\n` 分隔、UTF-8，存成 `ziwei-lab/synthetic-births-v1.txt`；產生器版本 `synth-births-v1`。清單的 SHA-256 在凍結時寫入 log（§3）。

## 11. 與年齡無關（CEO O4）

規則只能用兩種量：**本命盤**，以及**流日天干**和它的四化落在本命盤的哪一宮。不得使用大限、小限、流年、流月、童限，也不使用流日命宮。所以出生前的期數也有定義，合成生辰涵蓋 1950–2010，每一期都能挑號。

**流日命宮口徑（OQ2）：v1 不使用流日命宮。** 流日四化以「落本命盤宮位」計算，不需要流日命宮。這樣可以避開各流派口徑不同的問題，也不必依賴未驗證的 iztro horoscope 日期參數。

## 12. 池內打分公式與同分處理（OQ1）

**第 1 步：流日四化落宮。** 取 issueDate 的日干 g，查實驗口徑的四化表，得到化祿、化權、化科、化忌四顆星。在本命盤上找出各星所在宮的地支：`Z_祿`、`Z_權`、`Z_科`、`Z_忌`。四化表以 engineTag 的 ZiweiKit 為準；下表是原版預設，凍結前用 golden 核對：

| 日干 | 祿 | 權 | 科 | 忌 |
|---|---|---|---|---|
| 甲 | 廉貞 | 破軍 | 武曲 | 太陽 |
| 乙 | 天機 | 天梁 | 紫微 | 太陰 |
| 丙 | 天同 | 天機 | 文昌 | 廉貞 |
| 丁 | 太陰 | 天同 | 天機 | 巨門 |
| 戊 | 貪狼 | 太陰 | 右弼 | 天機 |
| 己 | 武曲 | 貪狼 | 天梁 | 文曲 |
| 庚 | 太陽 | 武曲 | 太陰 | 天同 |
| 辛 | 巨門 | 太陽 | 文曲 | 文昌 |
| 壬 | 天梁 | 紫微 | 左輔 | 武曲 |
| 癸 | 破軍 | 巨門 | 太陰 | 貪狼 |

**第 2 步：號碼對應。** 紅球和藍球用同一套對應。
- 地支：`支(n) = (n − 1) mod 12`，0 = 子、1 = 丑 … 11 = 亥。
- 五行（河圖數）：取 `n mod 10`，0 當成 10。1、6 → 水；2、7 → 火；3、8 → 木；4、9 → 金；5、10 → 土。
- 日干五行：甲乙 = 木、丙丁 = 火、戊己 = 土、庚辛 = 金、壬癸 = 水。

**第 3 步：單球分數。**

```
ball(n) = 2·[支(n) = Z_祿] + 1·[支(n) = Z_權] + 1·[支(n) = Z_科] − 2·[支(n) = Z_忌]
        + 1·[五行(n) = 日干五行]
```

（同一宮可以同時有多化，各項分別加總。）

**第 4 步：組分數與選擇。**

```
score(c) = Σ_{6 紅} ball(n) + ball(藍)
pick = argmax_{c ∈ pool_t} score(c)
```

同分時取字典序最小的組：先比紅球升冪序列，再比藍球。

**性質：** 規則是確定性的，只依 (本命盤, issueDate, pool_t) 決定，不用亂數。本命盤只算一次；每期只查一次四化表，再對 K 組打分。

## 13. 主統計量與個人百分位

- 每期分數 s（§1），單窗主統計量 `T = Σ_t s(pick_t, draw_t)`，兩窗分開算。
- 對照分布：10,000 個隨機挑選者，每期從 pool_t 均勻挑一組（種子見 §8），每人算一個 T。按窗發布 `control/hist-v1.json`、`control/live-v1.json`。
- 個人百分位：`P = (#{control < T} + 0.5 · #{control = T}) / 10,000`。
- 副指標（不做檢定）：中任一獎的期數、累計回收、所選組在池內的冷門指數排名（只在採用人氣池時顯示）。
